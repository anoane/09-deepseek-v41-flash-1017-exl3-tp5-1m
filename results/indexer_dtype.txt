# Lightning-indexer scoring precision (EXL3_DSA_INDEXER_DTYPE), 2026-10-20, engine 309ef6d1 (fork branch dsv41f-1017).
#
# End to end: tools/kv_eval.py, one model load per row, no draft head, plain forward loop (so decode here is not the
# server's figure). One chat of 1,016,849 tokens: a user turn holding the C / CUDA corpus of the long-prompt table
# (not published) with three planted release keys at 10 / 50 / 90 % of it, then a question about them. Prefilled
# in 16,384-token chunks; at four depths the next 1,024 corpus tokens are scored teacher-forced and compared with
# the FP16 run of the same layout: KL(fp16 || this), top-1 agreement, change of the corpus NLL (mean, standard
# error of the paired per-token differences). "Keys" = keys recalled in the greedy answer after the whole prompt.
# Noise floor of the same harness and layout (FP16, prefill chunk 8,192 instead of 16,384):
#   KL 0.0036 / 0.0030 / 0.0012 / 0.0002 at 16K / 131K / 524K / 1M, top-1 97.7 / 98.0 / 99.7 / 99.9 %.
# The engine's prefill is not bit-reproducible run to run (the FP16 NLL at 16K was 1.1583 in one run, 1.1561 in
# the next), so these are judged against that floor, not against bit equality.
